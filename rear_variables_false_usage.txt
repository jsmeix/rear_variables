       RELAX-AND-RECOVER (ReaR) - VARIABLE FALSE USAGE ANALYSIS REPORT
===============================================================================

1. PURPOSE AND REAR CODING GUIDELINES CONTEXT
---------------------------------------------
In Relax-and-Recover (ReaR), stage scripts (prep, rescue, build, backup,
output, restore, finalize, etc.) are executed by sequentially sourcing them
within the running Bash shell process via SourceStage() and Source() (defined
in usr/share/rear/lib/_framework-setup-and-functions.sh).

According to the official ReaR Coding Style guidelines
(https://github.com/rear/rear/wiki/Coding-Style):

  RULE 1: Cross-Script / Global Variables MUST be ALL-CAPS
    All variables that are used in more than a single script must be all-caps
    (e.g., $FOO instead of $foo or $Foo).

  RULE 2: Script-Local Variables MUST be Lowercase AND Marked 'local'
    Variables that are used only locally within a script or function must be
    lowercased (e.g., local foo="default_value") and marked with 'local'.
    Because scripts are sourced from within ReaR's Source() function, they
    run in a functional scope where 'local' is valid and supported.

  RULE 3: Variable Reuse Across Scripts is Intended ONLY When Marked 'local'
    It is intended and valid that independent scripts reuse the same
    lowercase variable names (e.g., 'zypper_backup_dir', 'disk_size', 'dev')
    PROVIDED each script marks them with 'local'. When marked 'local', each
    script gets its own isolated instance that terminates upon script return,
    preventing global leakage and variable collision.

CRITERIA FOR FALSE USAGE (VIOLATIONS REPORTED IN THIS FILE):
  1. Non-uppercase variable used in several scripts without being marked 'local'
     in all of those scripts. (If a script omits 'local', the variable leaks
     into the global shell environment and risks silent state corruption).
  2. Variable used in only one script that is NOT marked 'local'
     (A script-local variable that leaks into the outer scope because 'local'
     was omitted).
  3. Variable used in only one script that is named UPPERCASE
     (Violates Rule 1 & Rule 2: all-caps is reserved for variables used
     across scripts or user configuration. Single-script variables must be
     lowercased and marked 'local').

WHAT IS COMPLIANT (EXCLUDED FROM VIOLATIONS):
  - 259 multi-script non-uppercase variables that are strictly marked
    'local' in EVERY script where they are used (e.g., 'zypper_backup_dir').
  - 798 single-script non-uppercase variables that are strictly marked 'local'.
  - Uppercase variables that are used across multiple scripts (normal global/config).
